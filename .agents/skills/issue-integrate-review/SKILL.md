# Issue Review Integration Skill (`/issue-integrate-review`)

Use this skill to close the review loop on a GitHub issue. It discovers review comments (such as those generated by `/issue-review`), reconciles pending findings against the current issue state, refactors the main issue post to incorporate accepted recommendations and maintainer decisions (`[DEC-N]`), records an immutable audit ledger on the issue, posts a public resolution comment, and transitions triage labels.

---

## Key Capabilities

1. **Multi-Review Discovery & State Tracking**: Uses `.agents/scripts/issue_review_helper.sh --parse-reviews` to parse all review comments and detect pending vs already-integrated items.
2. **DEC Protocol Enforcement**: Verifies that all maintainer decisions (`[DEC-N]`) are fully resolved before integrating, halts without writes on unresolved or malformed reviews, and embeds decisions under `### 🧭 Maintainer Decisions`.
3. **Single-Ledger State Machine Model**: Tracks integration history, decisions, and decline rationale inside a hidden HTML block `<!-- issue-review-ledger: [...] -->` in the issue body, completely avoiding HTTP 403 Forbidden issues on third-party comments.
4. **Intent-Preserving Synthesis & Human Guidance**: Integrates architectural, security, and testing additions seamlessly into the issue body while strictly preserving author intent and applying human maintainer guidance comments.
5. **Boundary & SHA-256 Drift Protection**: Helper script enforces GitHub's 65,000-character issue body boundary and checks remote `body_sha256` before writing.
6. **Public Resolution & Best-Effort Patch**: Posts a clean, transparent resolution reply comment on GitHub carrying `<!-- ai-pipeline-notice: {"kind":"integration_resolution", ...} -->`, and performs a best-effort patch on the original review comment.
7. **Pipeline Mode Integration**: Respects pipeline mode (D13) by omitting label writes in automated pipelines, while transitioning labels from `needs-triage` and `needs-info` to `ready-for-agent` in manual runs.

---

## Pipeline Mode (D13)

When running inside the autonomous issue pipeline (`[[ -n "${PIPELINE_RUN_ID:-}" ]]`):
- **Lifecycle labels & assignees**: The reconciler owns all lifecycle label transitions (`ready-for-agent`, `in-progress`, `needs-info`, `ready-for-human`, `verified`) and assignees. Skills make **no** edits to these labels or assignees in pipeline mode.
- **Halts**: Preconditions and circuit breaker conditions still halt the skill, but without performing label side effects.
- **Markers**: Every comment posted by a skill carries an `<!-- ai-` marker in both modes.
- **Helper exits**: An exit code of 2 from any helper script indicates a GitHub/API failure and must halt the skill immediately.

## Human Guidance Comments

When reconciling issues, maintainer input posted after reviews provides authoritative guidance. The extraction rule strictly filters for human input:
- **Fetch**: `gh issue view <number> --json comments`.
- **Trusted author**: `TRUSTED="${GH_TRUSTED_AUTHOR:-$(gh api user -q .login)}"`.
- **Machine comment**: `author.login == $TRUSTED` **and** the body matches `<!--\s*ai-`. These are never guidance.
- **Human input**: not a machine comment **and** (`author.login == $TRUSTED` **or** `authorAssociation ∈ {OWNER, MEMBER, COLLABORATOR}`). A missing or unknown `authorAssociation` from any other author is not guidance (fail closed).
- **Cutoff**: Only human-input comments with `createdAt` strictly after `CUTOFF` count.
  - In `/issue-integrate-review`, `CUTOFF` is the `createdAt` timestamp of the latest **machine** `<!-- ai-pipeline-notice` comment on the issue. If there is none, it is the target review comment's `createdAt`.
- **Reference `jq` Filter**:
  ```bash
  jq --arg trusted "$TRUSTED" --arg after "$CUTOFF" '[.comments[]
    | select(.createdAt > $after)
    | select(((.author.login == $trusted) and ((.body // "") | test("<!--\\s*ai-"))) | not)
    | select(.author.login == $trusted or (.authorAssociation | IN("OWNER","MEMBER","COLLABORATOR")))]'
  ```
- Guidance comments are applied chronologically; on conflict, the latest comment wins.

## Step-by-Step Execution Protocol

### Step 1: Ingestion & Multi-Review Discovery

1. **Parse Target Issue & Resolve Model**:
   - Extract issue number from argument (e.g. `#42` or `42`).
   - If not provided, prompt the user for the target issue number.
   - Resolve active model slug:
     ```bash
     MODEL="$(bash .agents/scripts/issue_lifecycle_helper.sh --resolve-model ${MODEL_FLAG:-})"
     ```

2. **Fetch Complete Issue State**:
   ```bash
   gh issue view <number> --json number,title,body,author,labels,comments,updatedAt > /tmp/issue_<number>_full.json
   ```

3. **Parse Review State**:
   Execute the helper script to extract structured review status:
   ```bash
   if ! bash .agents/scripts/issue_review_helper.sh --parse-reviews --file /tmp/issue_<number>_full.json > /tmp/issue_<number>_parsed.json; then
     echo "Error: Failed to parse reviews for issue <number>" >&2
     exit 2
   fi
   ```

4. **Select Target Review & Evaluate Discovery**:
   - Inspect `/tmp/issue_<number>_parsed.json`:
     - If `reviews` is empty: Report that no review comments were found on the issue.
     - If `pending_items` is empty and no pending reviews exist: Report that all reviews have already been integrated into the ledger.
     - Select target review `REVIEW_ID`. If `--comment-id` is specified, filter to that review; otherwise, select the oldest unresolved pending review.

5. **Decision & Malformation Guard (D10)**:
   Verify that the target review is valid and has no unresolved maintainer decisions:
   ```bash
   REVIEW_STATUS="$(jq -r --arg rid "$REVIEW_ID" '.reviews[] | select(.review_id == $rid) | .status' /tmp/issue_<number>_parsed.json)"
   if [[ "$REVIEW_STATUS" == "malformed" ]]; then
     echo "Error: Target review $REVIEW_ID is malformed. Integration halted." >&2
     exit 1
   fi
   UNRESOLVED_COUNT="$(jq --arg rid "$REVIEW_ID" '[.unresolved_decisions[] | select(.review_id == $rid)] | length' /tmp/issue_<number>_parsed.json)"
   if [[ "$REVIEW_STATUS" == "awaiting_decision" && "$UNRESOLVED_COUNT" -gt 0 ]]; then
     echo "Error: Review $REVIEW_ID requires maintainer decisions before integration ($UNRESOLVED_COUNT unresolved):" >&2
     jq --arg rid "$REVIEW_ID" '[.unresolved_decisions[] | select(.review_id == $rid)]' /tmp/issue_<number>_parsed.json >&2
     exit 1
   fi
   ```

---

### Step 2: Critical Integration Analysis & Guidance Ingestion

1. **Ingest Human Guidance**:
   Extract human guidance comments posted after the latest pipeline notice or review comment:
   ```bash
   TRUSTED="${GH_TRUSTED_AUTHOR:-$(gh api user -q .login)}"
   CUTOFF="$(jq -r --arg rid "$REVIEW_ID" '
     [.comments[] | select((.body // "") | test("<!--\\s*ai-pipeline-notice:")) | .createdAt] | last //
     (.reviews[] | select(.review_id == $rid) | .metadata.timestamp) // ""
   ' /tmp/issue_<number>_parsed.json)"

   GUIDANCE_COMMENTS="$(jq --arg trusted "$TRUSTED" --arg after "$CUTOFF" '[.comments[]
     | select(.createdAt > $after)
     | select(((.author.login == $trusted) and ((.body // "") | test("<!--\\s*ai-"))) | not)
     | select(.author.login == $trusted or (.authorAssociation | IN("OWNER","MEMBER","COLLABORATOR")))]' /tmp/issue_<number>_full.json)"
   ```

2. **Process Pending Findings & Decisions**:
   For each pending item in the targeted review:
   - **DEC Items (`[DEC-N]`)**: Must ALWAYS be applied according to the maintainer's selected option or custom answer. DEC items may **never** be declined. Every `DEC-N` key goes into `APPLIED_KEYS` and into structured `DECISIONS`.
   - **Technical Findings (`[ARCH-N]`, `[SEC-N]`, etc.)**:
     - **Apply**: Valid finding. Incorporate into issue specification.
     - **Decline**: Invalid, redundant, or contradicts domain rules in `GEMINI.md`. Formulate concise technical rationale.
   - If an irreconcilable conflict arises that no DEC covers, use the **Escape Hatch**:
     - Do not modify the body.
     - Post an explanatory comment with marker:
       ```bash
       gh issue comment <number> --body "<!-- ai-pipeline-notice: {\"kind\":\"needs_input\",\"review_id\":\"$REVIEW_ID\"} -->
### ❓ Clarification Needed on Review $REVIEW_ID
<Explanation of the conflict>"
       ```
     - In manual runs, apply `needs-info`:
       ```bash
       if [[ -z "${PIPELINE_RUN_ID:-}" ]]; then
         gh issue edit <number> --add-label "needs-info"
       fi
       ```
     - Halt.

3. **Prepare Arrays**:
   - `APPLIED_KEYS`: JSON array of string IDs, e.g. `'["ARCH-1", "SEC-1", "DEC-1"]'`
   - `DECLINED_ITEMS`: JSON array of objects, e.g. `'[{"id": "OPT-1", "reason": "Dynamic reallocation preferred per ADR-002"}]'`
   - `DECISIONS`: Structured objects from the target review's parsed decisions:
     ```bash
     DECISIONS="$(jq -c --arg rid "$REVIEW_ID" '[.reviews[] | select(.review_id == $rid) | .decisions[]
       | {id, selected, custom_answer}]' /tmp/issue_<number>_parsed.json)"
     ```

---

### Step 3: Issue Body Synthesis & Guardrails

1. **Synthesize Updated Issue Body**:
   - Read the original issue body:
     ```bash
     jq -r .body /tmp/issue_<number>_full.json > /tmp/issue_<number>_orig.md
     ```
   - Update the markdown content:
     - Preserve title, overview, background, and core author intent.
     - If DEC items exist, record each under `### 🧭 Maintainer Decisions`.
     - Inject or update relevant specification sections.
     - Append a clean revision note:
       ```markdown
       ---
       <sub>*Updated on <YYYY-MM-DD> via `/issue-integrate-review` using `<MODEL>` incorporating findings from Review `<review_id>`.*</sub>
       ```
   - Save to `/tmp/issue_<number>_synth.md`.

2. **Safely Update Ledger & Enforce Guardrails**:
   Use the helper script to append the hidden ledger block:
   ```bash
   bash .agents/scripts/issue_review_helper.sh --append-ledger \
     --issue <number> \
     --review-id "$REVIEW_ID" \
     --comment-id "$COMMENT_ID" \
     --model "$MODEL" \
     --applied "$APPLIED_KEYS" \
     --declined "$DECLINED_ITEMS" \
     --decisions "$DECISIONS" \
     --input-body-file /tmp/issue_<number>_synth.md \
     --output-body-file /tmp/issue_<number>_final.md
   ```

3. **Verify Remote Drift & Update Issue**:
   - Check that no concurrent edits occurred since ingestion:
     ```bash
     INGESTION_SHA="$(jq -r .body_sha256 /tmp/issue_<number>_parsed.json)"
     bash .agents/scripts/issue_review_helper.sh --check-drift <number> --body-sha256 "$INGESTION_SHA"
     ```
   - If `--dry-run` was requested:
     - Print a diff between `/tmp/issue_<number>_orig.md` and `/tmp/issue_<number>_final.md`.
     - Stop before updating GitHub.
   - Otherwise, update the issue body:
     ```bash
     gh issue edit <number> --body-file /tmp/issue_<number>_final.md
     ```

---

### Step 4: Public Resolution Comment & Checklist Reconciliation

1. **Compose Public Resolution Comment**:
   Create `/tmp/issue_<number>_resolution.md` starting with canonical machine marker:
   ```markdown
   <!-- ai-pipeline-notice: {"kind":"integration_resolution","review_id":"<REVIEW_ID>"} -->
   ### ✅ Integrated Review `<REVIEW_ID>`
   **Integrated By:** `<MODEL>`

   The main issue post has been updated with accepted findings and maintainer decisions:
   - [x] **[DEC-1]**: Applied maintainer decision: <selected option or custom answer> *(Integrated)*
   - [x] **[ARCH-1]**: Refactor account reallocation to header-only dynamic sizing *(Integrated)*
   - [x] **[SEC-1]**: Enforce canonical bump validation on vault authority PDA *(Integrated)*
   - [ ] ~~**[OPT-1]**: Use zero-copy array~~ *(Declined: Dynamic reallocation preferred per ADR-002)*

   ---
   <sub>*Audit record stored in issue ledger.*</sub>
   ```

2. **Publish Resolution Comment**:
   ```bash
   gh issue comment <number> --body-file /tmp/issue_<number>_resolution.md
   ```

3. **Best-Effort Review Comment Patch**:
   Attempt to update the checklist on the original review comment:
   ```bash
   bash .agents/scripts/issue_review_helper.sh --patch-comment "$COMMENT_ID" /tmp/patched_review_${COMMENT_ID}.md
   ```

---

### Step 5: Triage Label Transition

1. **Re-parse Review Status**:
   ```bash
   bash .agents/scripts/issue_review_helper.sh --parse-reviews --issue <number> > /tmp/issue_<number>_recheck.json
   ```

2. **Transition Triage Label (Manual Mode Only)**:
   - Check if any `pending_items` or unresolved decisions remain.
   - If all reviews are resolved, transition labels in manual mode:
     ```bash
     if [[ -z "${PIPELINE_RUN_ID:-}" ]]; then
       gh issue edit <number> --remove-label "needs-triage" --remove-label "needs-info" --add-label "ready-for-agent"
     fi
     ```
     *(In pipeline mode per D13, label edits are skipped; the reconciler owns `ready-for-agent`).*

3. **Present Summary Report**:
   Present a clear summary to the developer:
   - Issue number and title.
   - Review ID integrated.
   - Applied findings count and DEC decisions recorded.
   - Declined findings count and reasoning.
   - Updated labels on the issue.
   - Direct link to the issue on GitHub.
