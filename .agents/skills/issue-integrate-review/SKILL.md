# Issue Review Integration Skill (`/issue-integrate-review`)

Use this skill to close the review loop on a GitHub issue. It discovers review comments (such as those generated by `/issue-review`), reconciles pending findings against the current issue state, refactors the main issue post to incorporate accepted recommendations, records an immutable audit ledger on the issue, posts a public resolution comment, and transitions triage labels.

---

## Key Capabilities

1. **Multi-Review Discovery & State Tracking**: Uses `.agents/scripts/issue_review_helper.sh --parse-reviews` to parse all review comments and detect pending vs already-integrated items.
2. **Single-Ledger State Machine Model**: Tracks integration history and decline rationale inside a hidden HTML block `<!-- issue-review-ledger: [...] -->` in the issue body, completely avoiding HTTP 403 Forbidden issues on third-party comments.
3. **Intent-Preserving Synthesis**: Integrates architectural, security, and testing additions seamlessly into the issue body while strictly preserving the author's core motivation and scope.
4. **Boundary & Drift Protection**: Helper script enforces GitHub's 65,000-character issue body boundary and checks remote `updatedAt` timestamps before writing.
5. **Public Resolution & Best-Effort Patch**: Posts a clean, transparent resolution reply comment on GitHub with GFM crossed-out items for declined points, and performs a best-effort patch on the original review comment.
6. **Automatic Triage Transition**: Transitions issue triage labels (e.g. from `needs-triage` to `ready-for-agent`) per `docs/agents/triage-labels.md` once all reviews are resolved.

---

## Step-by-Step Execution Protocol

### Step 1: Ingestion & Multi-Review Discovery

1. **Parse Target Issue**:
   - Extract issue number from argument (e.g. `#42` or `42`).
   - If not provided, prompt the user for the target issue number.

2. **Fetch Complete Issue State**:
   ```bash
   gh issue view <number> --json number,title,body,author,labels,comments,updatedAt > /tmp/issue_<number>_full.json
   ```

3. **Parse Review State**:
   Execute the helper script to extract structured review status:
   ```bash
   bash .agents/scripts/issue_review_helper.sh --parse-reviews --file /tmp/issue_<number>_full.json > /tmp/issue_<number>_parsed.json
   ```

4. **Evaluate Discovery Results**:
   - Inspect `/tmp/issue_<number>_parsed.json`:
     - If `reviews` is empty: Report that no review comments (`<!-- ai-issue-review:` or `# Issue Review`) were found on the issue.
     - If `pending_items` is empty: Report that all review comments on this issue have already been integrated into the ledger.
     - If pending reviews exist: Select the target review(s). If `--comment-id` is specified, filter to that review; otherwise, process the pending review(s).

---

### Step 2: Critical Integration Analysis

For each pending item in the targeted review:
1. **Verify Semantic Validity**:
   - Check if the finding has already been implemented or rendered obsolete by prior commits.
   - Verify that the recommendation complies with protocol standards in `GEMINI.md` (e.g. pre-production clean architecture, no legacy shims, LiteSVM test requirements).
   - Check against domain invariants in `docs/adr/` or `docs/agents/`.

2. **Categorize Item**:
   - **Apply**: The finding is valid and must be incorporated into the main issue post. Formulate the exact text, diagram, or test vector to add.
   - **Decline**: The finding is invalid, contradictory, or redundant. Formulate a concise, concrete technical reason (e.g. `"Dynamic reallocation preferred over fixed arrays per ADR-002"`).

3. **Prepare Arrays**:
   - `APPLIED_KEYS`: JSON array of string IDs, e.g. `'["ARCH-1", "SEC-1"]'`
   - `DECLINED_ITEMS`: JSON array of objects, e.g. `'[{"id": "OPT-1", "reason": "Dynamic reallocation preferred per ADR-002"}]'`

---

### Step 3: Issue Body Synthesis & Guardrails

1. **Synthesize Updated Issue Body**:
   - Read the original issue body:
     ```bash
     jq -r .body /tmp/issue_<number>_full.json > /tmp/issue_<number>_orig.md
     ```
   - Update the markdown content:
     - Preserve the issue's original title, overview, background, and author intent.
     - Inject or update relevant sections (e.g. Architecture, Account Layouts, Security Invariants, Test Scenarios).
     - If the issue does not have explicit sections, add an **"### 🛠️ Review Amendments & Implementation Specifications"** section at the bottom.
     - Append a clean revision note:
       ```markdown
       ---
       <sub>*Updated on <YYYY-MM-DD> via `/issue-integrate-review` incorporating findings from Review `<review_id>`.*</sub>
       ```
   - Save the synthesized markdown to `/tmp/issue_<number>_synth.md`.

2. **Safely Update Ledger & Enforce Guardrails**:
   Use the helper script to append/update the hidden ledger block and enforce character limits:
   ```bash
   bash .agents/scripts/issue_review_helper.sh --append-ledger \
     --issue <number> \
     --review-id "<review_id>" \
     --comment-id <comment_id> \
     --applied '<APPLIED_KEYS_JSON>' \
     --declined '<DECLINED_ITEMS_JSON>' \
     --input-body-file /tmp/issue_<number>_synth.md \
     --output-body-file /tmp/issue_<number>_final.md
   ```

3. **Verify Remote Drift & Update Issue**:
   - Check that no concurrent edits occurred since ingestion:
     ```bash
     INGESTION_TIMESTAMP="$(jq -r .updated_at /tmp/issue_<number>_parsed.json)"
     bash .agents/scripts/issue_review_helper.sh --check-drift <number> "$INGESTION_TIMESTAMP"
     ```
   - If `--dry-run` was requested:
     - Print a diff between `/tmp/issue_<number>_orig.md` and `/tmp/issue_<number>_final.md`.
     - Stop before updating GitHub.
   - Otherwise, update the issue body:
     ```bash
     gh issue edit <number> --body-file /tmp/issue_<number>_final.md
     ```

---

### Step 4: Public Resolution Comment & Checklist Reconciliation

1. **Compose Public Resolution Comment**:
   Create `/tmp/issue_<number>_resolution.md` with full transparency on applied and declined items:
   ```markdown
   ### ✅ Integrated Review `<review_id>`

   The main issue post has been updated with accepted findings:
   - [x] **[ARCH-1]**: Refactor account reallocation to header-only dynamic sizing *(Integrated)*
   - [x] **[SEC-1]**: Enforce canonical bump validation on vault authority PDA *(Integrated)*
   - [ ] ~~**[OPT-1]**: Use zero-copy array~~ *(Declined: Dynamic reallocation preferred per ADR-002)*

   ---
   <sub>*Audit record stored in issue ledger.*</sub>
   ```

2. **Publish Resolution Comment**:
   ```bash
   gh issue comment <number> --body-file /tmp/issue_<number>_resolution.md
   ```

3. **Best-Effort Review Comment Patch**:
   Attempt to update the checklist on the original review comment:
   ```bash
   # Build patched comment with updated checkmarks and crossed out declined items
   bash .agents/scripts/issue_review_helper.sh --patch-comment <comment_id> /tmp/patched_review_<comment_id>.md
   ```
   *(If 403 Forbidden is returned, the helper script gracefully warns and continues without failing).*

---

### Step 5: Triage Label Transition

1. **Re-parse Review Status**:
   ```bash
   bash .agents/scripts/issue_review_helper.sh --parse-reviews --issue <number> > /tmp/issue_<number>_recheck.json
   ```

2. **Transition Triage Label**:
   - Check if any `pending_items` remain across all reviews.
   - If all reviews are fully resolved, check current labels against `docs/agents/triage-labels.md`:
     ```bash
     # If issue currently has "needs-triage", transition to "ready-for-agent"
     gh issue edit <number> --remove-label "needs-triage" --add-label "ready-for-agent"
     ```

3. **Present Summary Report**:
   Present a clear summary to the developer:
   - Issue number and title.
   - Review ID integrated.
   - Applied findings count and list.
   - Declined findings count and reasoning.
   - Updated labels on the issue.
   - Direct link to the issue on GitHub.
